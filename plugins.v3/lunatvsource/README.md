# LunaTV 资源订阅（MoviePilot V3）

独立的 MoviePilot V3 插件，读取 MoonTV/LunaTV 的 `api_site` 配置，接入标准苹果 CMS V10 资源站。

## 当前范围

- 读取可配置的 LunaTV JSON 配置地址；默认使用个人可维护的配置仓库。
- 默认读取订阅地址内的全部资源站，单个源失败不阻塞其它源；只有显式填写旧版白名单时才过滤。
- 来源清单与搜索健康默认每 60 分钟后台刷新一次（可配置 15–1440 分钟）；打开插件页只读取持久化缓存，不会现场逐源请求。
- 新增或端点变化的来源必须先通过搜索协议健康检查；未检查、配置已标记为不支持/污染/无搜索结果的来源不会参与搜索与订阅追更。协议响应异常或实时检查失败只记录网络状态和失败次数，来源仍会尝试调用；自动禁用源按周期复测并在恢复后重新启用。合法的空搜索列表只表示本次关键词未命中，不会被误判为故障。
- 工作台支持手动永久停用来源；手动停用跨插件重启和远端配置刷新保留，直到用户重新启用；重新启用后立即恢复调用，并按需点击测试或等待周期检查。
- 使用 MoviePilot 活跃订阅名称搜索资源。
- 参与 MoviePilot 原生全局搜索与资源搜索，不再注册重复的 `LunaTV / 苹果 CMS` 探索标签；结果带有稳定的 `lunatv` 媒体身份，可继续创建订阅。
- 电视剧资源按“来源 + 季”显示为一个原生资源卡片；下载时按整季处理。电影仍是一部一个资源项，多来源不会被同一播放地址误合并。
- 下载队列默认同时运行 2 个任务，每个任务使用 16 个分片线程；任务数可配置范围为 1–4，分片线程可配置范围为 4–32，二者乘积会限制在 64 以内。同一目标文件始终串行，避免不同来源争用同一个 `.part` 或成品文件。
- 支持 m3u8/HTTP 资源下载到指定目录，或生成 `.strm`；HLS 去广告仅在“下载到本地并整理”模式执行，STRM 保留原始播放直链。
- 单源下载失败（403 / 源失效 / 连接异常）时可自动改用同一集在其它资源站的地址重试，全部候选都试过才判定失败；默认开启，可用开关和上限关闭或收敛。
- 默认调用 MoviePilot 原生整理链；插件只在宿主链不可用时保留直写结果，完成记录统一回到 MoviePilot 原生历史。
- 下载完成后沿用 MoviePilot 已启用媒体服务器设置触发媒体库刷新；播放不放在插件页，仍由既有媒体服务器页面负责。
- 原生下载管理会投影插件任务的季集、可用时的 VOD 进度、暂停/继续和删除操作；暂停或删除运行中任务会先安全终止当前下载进程，不把虚拟任务转发给 qBittorrent。
- 原生整季删除默认只移除任务并保留已完成文件；只有 MoviePilot 明确传入“删除文件”选项时才清理下载目录内对应文件。
- 订阅刷新同时检查 MoviePilot 原生 TMDB 下载历史；即使整理方式移动了下载源文件，已经完成的电影或电视剧季集也不会被再次排队。
- MoviePilot 活跃电视剧订阅默认每 30 分钟检查一次：首次补齐所有缺集，后续只加入新增集；选择来源时先保证最新季集完整，再比较清晰度。
- 工作台持久显示最近一次追更、媒体库同步和订阅进度回填结果；重启后仍可查看最后失败原因和完成时间。
- 自动复用 MoviePilot“智能助手配置”（DeepSeek 等 OpenAI 兼容模型）清理片名后再搜索；未配置或调用失败自动回退原名称。
- 搜索结果自动调用 MoviePilot 原生识别链关联 TMDB；TMDB 能提供完整季集数时，会帮助拆分平铺的多季合集。
- 搜索结果会显示默认 TMDB 关联；同名或多季作品可重新搜索候选并手动切换，所选作品的季集数会参与安全拆分。
- 插件设置只保留一个下载目录，可留空自动复用 MoviePilot 传入目录、订阅保存目录或按媒体类型的本地下载目录；显式填写时优先写入该暂存目录。
- 任务通知通过 MoviePilot 插件消息能力发送；MoviePilot 的媒体库扫描可以继续接管已完成文件。

## 目录与命名

下载目录可显式填写为 MoviePilot 容器内存在且可写的路径；留空时按 MoviePilot 传入目录、订阅保存目录和媒体类型本地下载目录依次选择。下载完成后继续交给 MoviePilot 原生整理链，媒体库目录和整理规则无需在插件中重复配置。

整理落点由 MoviePilot 的“目录设置 + 二级分类策略”决定：插件把识别结果原样交给宿主，再用宿主给出的目标目录调用原生整理链，因此动漫、日番、国产剧、欧美剧、外语电影等分类会分别落到各自配置的媒体库目录，不需要在插件里维护任何目录规则。

下载暂存目录的分类行为与片源下载一致：只有把插件下载目录填成 MoviePilot 目录设置里某个下载目录的**根路径**时，才会在该根下按分类追加子目录（例如 `下载根/国产剧`）；填未登记路径或更深的自定义子目录时保持原样，整理阶段仍会按分类正确入库。识别不到媒体信息或宿主导不出可用媒体库目录时会回退旧整理路径，只降级不放弃，已完成文件不会丢失。

```text
电影名 (年份)/电影名 (年份).mp4
剧名 (年份)/Season 01/剧名 (年份) - S01E01.mp4
```

下载先写入 `.part`，成功后再改为正式文件名，避免媒体库扫描到半成品。目录内没有正在下载的缓存文件时，媒体库才会显示完整文件夹；MoviePilot/Emby 的自动监控建议在确认前暂时关闭。

M3U8 VOD 下载仅使用 [N_m3u8DL-RE](https://github.com/nilaoda/N_m3u8DL-RE)。插件随包携带官方 `v0.5.1-beta` Linux x64/arm64 release 原包及 MIT 许可证，安装前同时校验归档和可执行文件的固定 SHA-256；仅当对应内置包缺失时才从同一官方 GitHub release 下载。N_m3u8DL-RE 负责下载与混流；FFmpeg 仅作为其混流依赖，不是插件的回退下载器。暂停、失败和重启恢复会保留同一任务的专用缓存以便续传；仅成功或删除任务才清理缓存。

同一集只会进入一次任务；失败后重新提交会复用原任务，MoviePilot 重启时会清理旧版本遗留的重复记录，并把真正中断的任务恢复为待处理。详情接口缺少播放地址时，插件会自动补查 Apple CMS `ac=detail`，并识别 `S01E01`、`第 8 集`、`第 1 季` 等标记。只有线路或 TMDB 季集数能确定边界时才会按季聚合 `1-8 季`，无法确认时才退回单集，避免静默错放。

## 配置

默认配置地址：

```text
https://raw.githubusercontent.com/hafrey1/LunaTV-config/main/LunaTV-config.json
```

建议先只启用自己确认可用、且有权访问的资源源。插件不会绕过 DRM、登录保护或付费限制。

使用顺序：在插件卡片里保存订阅地址、下载目录并启用原生桥接 → 使用 MoviePilot 顶部全局搜索查找媒体并进入原生详情页 → 通过“搜索资源”或原生订阅触发 LunaTV 资源匹配 → 资源统一下载到暂存目录 → 下载完成后由 MoviePilot TMDB 整理链和媒体库同步接管。插件不增加独立探索或订阅导航。媒体库目录、智能助手、TMDB、媒体服务器和链接权限无需在插件中重复配置。

插件工作台只负责诊断、排队和状态，不内置 m3u8 播放器。你已有 Emby 时，只需按 MoviePilot 原生媒体服务器设置完成映射，插件会沿用已启用的媒体服务器并自动请求同步。第三方组件及其版权仍归各自权利人所有，使用时请遵循其许可证；详见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 下载失败自动换源

同一部剧的同一集往往在多个资源站上都有播放地址。资源站的直链是**易失**的：上游换域名、加防盗链、临时下线都会让原本可用的地址突然返回 403 或直接超时。换源功能就是在“下载阶段”为这种情况兜底——搜索期已经有来源健康检查，但健康检查通过不代表下载那一刻直链仍然有效，换源是最后一层保险。

### 配置方式

在插件卡片中「来源策略」下方有两个表单项：

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 下载失败自动换源 | 开关 | 开 | 关闭后所有下载失败都直接判定为失败，退回到旧行为 |
| 换源最多尝试几个备选站 | 数字，0–5 | 2 | 单个任务最多额外尝试几个备选源；填 `0` 等同于关闭换源 |
| 无进展多久判定卡住（分钟） | 数字，0–240 | 15 | 下载中但进度长时间不动超过该时长即中止并自动换源；填 `0` 关闭看门狗（只有真正失败才换源） |

三个配置项都带 `persistentHint`，属于持久化配置，随插件配置一起保存。旧版本配置里没有这些键时，读取逻辑按“开关=开、上限=2、卡住阈值=15 分钟”处理，也就是说**升级后默认开启**，不需要手动配置。

### 切换逻辑

1. **建候选表**：在 `source_strategy="first"`（“按配置顺序选一个”）下，插件本来会把匹配结果截断成排名第一的那个源。换源把候选表建立在**截断之前**——收集这一集在**所有**匹配源上的播放地址，按搜索结果排名排序、同址去重，得到 `{(季, 集): [url, ...]}`。截断后只剩一个源，备选地址就永久丢失了，所以这一步必须在截断前完成。
2. **带候选入队**：构造每个下载任务时，从候选表取出该集的地址列表，剔除当前正在使用的那个，截断到配置的上限，写入任务的 `alt_urls`。`alt_urls` 只在该集匹配到**多个源**时才非空（单源场景本就是空，换源无意义）。
3. **失败轮转**：下载失败且**不是用户主动暂停/删除**时，把当前地址记入 `failed_urls`，取 `alt_urls` 中第一个没试过的地址，任务回到 `pending` 并替换 `url`，进度与重试计数清零，继续下载。
4. **有界终止**：每个地址最多尝试一次（`failed_urls` 保证幂等，同一源绝不会被反复重试）。候选全部试完仍失败时，任务才写入终态 `failed`，失败通知带上“（已尝试 N 个源均失败）”。
5. **复用任务也换源**：失败的旧任务在后续扫描被复用时，会先把这次扫描新发现备选地址并入 `alt_urls`，再优先后一个未试过的地址，而不是原样重排那个已知失效的链接。

> 以上 1–5 是「下载失败自动换源」的基础行为（0.4.86）。0.4.87 在此基础上增强了**源头覆盖**，专门解决“候选池里只有死链”的场景（例如旧任务、`alt_urls` 收的全是 403/404 的源）。两项增强都**仅在 `source_strategy="first"` 下生效**（`all` 本身多源并行，不存在“换”的概念）。

6. **入队探针挑活链（0.4.87）**：构造 `alt_urls` 时，先用健康探针 `_probe_resource_urls` 探测候选地址的可用性（返回高度 > 0 视为活链），**优先采用活链**、按质量降序截断到上限；若所有候选探测失败，则回退原始候选列表（运行时仍可由第 7 步兜底）。这样第一跳尽量不撞 404/403 死链。
7. **失败用尽后跨源重搜（0.4.87）**：当任务自身的 `alt_urls` 全部试过仍失败时，插件会在**不持有下载队列锁**的情况下，跨**所有**资源站重新搜索本集（季、集），用健康探针筛出活链、按质量降序截断到上限，剔除已试过的地址后并入 `alt_urls` 继续轮转。这一步把候选池从源头扩充到“所有含该剧的源”，使原本只有死链的旧任务也能真正绕过死源继续下载。

8. **无进展看门狗（0.4.88）**：第 1–7 步都只在“下载**失败**”时触发，覆盖不到「一直卡在下载中、既没完成也没报错」的任务——这类下载会永远挂在 `running` 状态、占着并发槽位，谁也不会去动它。看门狗为每个任务记录进度最后一次推进的时刻（`last_progress_at`），由插件的定时扫描（每 `queue_minutes` 分钟，默认 1 分钟）驱动检查：running 任务的进度静止超过设定分钟数，就中止当前下载，然后走**与失败完全相同**的换源轮转（下一个备选 → 用尽后跨源重搜 → 终态）。进度**仍在推进**的慢下载不会被误判；`N_m3u8DL-RE` 会把自己的投影钳在 0.99，因此达到封顶值仍视为“存活”，只有引擎彻底无输出才算卡住。

> 第 8 步解决的是“卡住”，第 1–7 步解决的是“失败”，两者共用同一套**有界**轮转，互不冲突：看门狗只负责把静默卡死转成一次换源机会，之后仍受 `alt_urls` 与 `failed_urls` 的幂等约束（每个地址至多一次）。

换源过程中的通知标题为「LunaTV 自动换源」，正文只显示源站 host（不打印完整播放链接），并提示剩余候选数量；经跨源重搜切换时，文案会标注“已跨源搜索并切换到备选源”。

### 适用场景

- **适用**：`source_strategy` 为“按配置顺序选一个”时，单源直链因上游变动失效——返回 403、连接被拒、域名解析失败、下载中途截断等。
- **不适用**：`source_strategy` 为“所有匹配源都排队”时，多源本来就是并行入队，不存在“换”的概念，配置项对它不起作用。
- **退化即旧行为**：该集只匹配到一个源（候选表为空），或备选上限设为 `0`，或开关关闭时，任务不带任何候选，失败即失败，与升级前完全一致。
- **不涉及**：`.strm` 只写直链、不下载，STRM 模式下的直链失效由播放端承担，换源不介入。
- **网络依赖**：第 7 步“跨源重搜”需要能访问各资源站搜索接口并执行健康探针。若搜索接口不可达、探针全失败、或解析器自身抛异常，会**安静退化**为“候选用尽即失败”的旧终态，不会卡住队列或无限重搜。
- **只解决“有別的源有活链”的场景**：跨源重搜能把候选池扩充到所有含该剧的源，但**不能凭空产生地址**——若全网下架（所有源都搜不到本集、或搜到但探针全死），任务最终仍会判定失败。换源是“绕过失效直链”的兜底，不是“补源”。
- **看门狗只管「静默卡死」，不管「下载慢」**：判定依据是进度**不再推进**，不是速度阈值。只要引擎还在输出进度（哪怕很慢）就不会被中止；只有引擎彻底无输出、任务长时间停在某个百分比时才接管。

### 对现有行为的影响

- **默认开启**：老配置缺键也按开启处理，只有显式关闭才回到旧行为。
- **不产生重复任务**：在“按配置顺序选一个”策略下，任务身份 `identity_key` 与来源无关，换源是**同一个任务**替换 `url` 后重试，队列里不会因此多出条目，也不会出现同一集被并行下载。
- **数据兼容**：任务持久化新增 `alt_urls` / `failed_urls` 两个字段，旧记录读取时默认空列表（等于“无备选”），解码时校验必须是字符串列表，坏数据被安全拒绝而不是崩溃。
- **失败通知升级**：只有终态失败会发通知，文案追加“已尝试 N 个源均失败”；换源中途的通知是独立的一条，便于区分“还在挣扎”和“真的失败”。
- **换源会重下**：切换地址后该任务从 0 重新下载，已有的 `.part`/缓存按原有逻辑处理；这是代价，也是换源能起作用的前提。
- **跨源重搜不持锁、不持久化**：第 7 步的跨源搜索与探针在下载队列锁**之外**执行（避免慢搜索阻塞下载派发），且只做查询不改写任何状态；只有确认拿到新活链、合并进 `alt_urls` 时才会持锁落盘。解析器抛异常时返回空、安静退化为旧终态，绝不无限重搜。
- **入队探针是“择优”不是“过滤到底”**：第 6 步若所有候选都探测失败，仍保留原始候选列表入队，由运行时第 7 步兜底；不会因为探针误判而把一个其实可用的源排除掉。
- **看门狗可关闭，且升级不误杀**：`stall_timeout_minutes` 填 `0` 即完全关闭，退回“只有真正失败才换源”的旧行为。默认 15 分钟；升级后首次扫描遇到没有时钟记录的老任务（0.4.88 之前持久化的）只做**回填**、不会中止，因此刚升级时正在下载的任务不会被瞬间判定卡住。
- **中止不等于删除**：卡住被中止后走的是换源轮转（同一个任务换 `url` 重试、进度清零），不丢任务、也不会多出条目；只有候选全部耗尽才写终态 `failed`。
- **看门狗由定时扫描驱动**：派发循环只在有待处理任务时才运行，队列里唯一的任务卡住时不会自检查，因此扫描挂在插件的定时服务上（默认每分钟一次），扫描本身另有 30 秒节流，不会频繁重读持久化队列。

## 发布与回滚

- 发布前必须通过 `.github/workflows/ci.yml`：完整测试、Python 编译、前端生产构建，以及 `dist` 已提交且可重复生成。
- 发布标签必须严格等于 `LunaTVSource_v<package.v3.json 中的版本>`；例如 `0.4.61` 只能使用 `LunaTVSource_v0.4.61`，标签与清单不一致时 CI 会拒绝。
- 为兼容 MoviePilot 的 Release 安装路径，同名发布还应附带小写资产 `lunatvsource_v<version>.zip`（例如 `lunatvsource_v0.4.61.zip`）；压缩包根目录直接放插件文件，不再套一层 `lunatvsource/` 目录。
- MoviePilot 更新后先核对插件版本、工作台最近追更/同步状态，再用一集新增内容验证“下载 → 原生整理 → 订阅进度递增 → Emby/Jellyfin 可见”的完整链路。
- 回滚前先停用插件，保留队列、缓存和已完成文件；不要删除持久化数据，也不要移动或覆盖旧标签。
- 回滚采用向前修复：撤销有问题的发布提交，提升一个补丁版本，重新通过同一 CI 后创建新的更高版本标签。这样 MoviePilot 能正常识别更新，历史版本和队列数据仍可追踪。
