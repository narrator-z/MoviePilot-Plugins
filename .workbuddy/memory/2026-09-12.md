## 排查「MP 里插件看不全」（按作者搜索只剩 1 个）——根因已定位

**现象**：在市场按作者搜 `narrator-z` 只能看到 1 个插件。

**根因：不是 bug，是市场页的 state=market 过滤设计**
- `app/application/plugin/catalog.py:509-520` `query()`：
  `market_plugins = [p for p in candidates if p.id not in installed_keys or p.has_update]`
  → 市场页**默认排除已安装且无更新的插件**。
- 本仓库 package.v3.json 里 author=narrator-z 的 5 个：JackettExtend / ChineseSubFinder /
  StuckDownloadGuard / NeoDBSource / ProwlarrExtend，前 4 个已安装（UserInstalledPlugins）
  被过滤，只剩 **ProwlarrExtend** 1 个 → 与现象完全吻合。
- JackettIndexer 未安装但 author="Claude"，作者搜不到；LunaTVSource author="OneBigMoon"。

**顺带查实的仓库问题（待修）**
1. `package.json` 是空 `{}` → 对未启用 VERSION_FLAG 的实例解析出 0 个插件（v3 不受影响）。
2. LunaTVSource 本仓库 0.4.60 **低于** jxxghp 仓库的 0.4.82 → 被跨仓库同名去重顶掉。
   （`catalog.py:370-386` result_by_id 按插件 ID 去重、版本号高者胜出）

## ⚠️ 更正旧结论：插件接口「默认只返回 50 条」在 v3.0.37 已不成立
- `app/api/endpoints/plugin.py:207` 现为 `max_results: Query(ge=1, le=200) = None`，
  且 `return plugins if max_results is None else plugins[:max_results]` → **不传分页返回全量**。
- 只有前端传了 `page` 或 `count` 任一参数才分页（`resolve_compatible_pagination`，默认 50）。
- 前端实测（`index-Bgbb1qk1.js`）：市场页 `get("plugin/", {params:{state:"market",force:e}})`
  **不带 page/count** → 全量。侧边栏用 `state:"installed"`。
- 所以「市场只显示 50 个」的旧记忆作废，别再按分页方向排查。

## ⚠️ 新坑：`plugin_author` 被 JackettIndexer 用于业务逻辑（改署名会炸）
- `plugins.v3/jackettindexer/__init__.py`：`JACKETT_DOMAIN = "jackett_indexer.claude"`，
  运行时 `domain = JACKETT_DOMAIN.replace(self.plugin_author.lower(), indexer_name)`。
- **占位符必须与 `plugin_author.lower()` 完全一致**，否则 replace 不命中 →
  所有索引器共用同一个 domain → 功能彻底失效。
