## ✅ 破解：本机无外网时经 NAS 中继 git push（已成功，可复用）
用户指出「不用代理」后实测：直连也不通（TCP 通但 TLS/SSH banner 全超时），是环境出口被拦。
解法 —— 借 NAS 出网（其 SSH key 已授权 GitHub `narrator-z`）：

```bash
# 1. 本机打包（路径用 Windows 风格，/c/... 有时认不出）
git bundle create "C:/Users/<u>/AppData/Local/Temp/mp-plugins.bundle" --all
# 2. 上传（本机 ssh/scp 到 NAS 免密可用，无需 -i 指定密钥）
scp -P 22022 <bundle> narratorz@192.168.31.145:/tmp/
# 3. NAS 上：clone 远端 → 拉 bundle → fast-forward → push
ssh -p 22022 narratorz@192.168.31.145 \
  "git clone git@github.com:narrator-z/MoviePilot-Plugins.git /tmp/mpp && cd /tmp/mpp &&
   git fetch /tmp/mp-plugins.bundle main && git merge --ff-only FETCH_HEAD && git push origin main"
# 4. 清理 NAS /tmp，并手动同步本机 remote-tracking（本机无法 fetch）
git update-ref refs/remotes/origin/main <new-sha>
```
- 验证：NAS 上 `curl https://raw.githubusercontent.com/narrator-z/MoviePilot-Plugins/main/package.v3.json`
  已返回 LunaTVSource `0.4.83`，基础索引 7 条 `"v3": true`。
- ⚠️ 附带发现：**本机 `origin/main` 长期陈旧**（记录 9bf576f，实际远端已是 5f14077），
  因为一直没成功 fetch 过。判断"有几个提交待推"必须看 `git log origin/main..main` 之外的真实远端状态，
  否则会误判多推/少推。

## 合并上游 LunaTVSource（0.4.60~0.4.82）+ 版本 bump（已推送）

**基线定位方法（关键，可复用）**：本仓库是手工建的（非 GitHub fork），无共同历史，
无法用 git merge。做法 —— 在 NAS 上 `git clone --unshallow` 上游仓库，遍历
`git log --format=%H -- plugins.v3/lunatvsource/__init__.py` 的每个提交，用 difflib 与本地
比对取差异最小者。结果：**本地基线 = 上游 0.4.59（03b0fd2，2026-08-30）**，仅 17 行差异。
（次优候选差异 259 行，差距明显，判定可靠。）

**⚠️ 坑：CRLF/LF 会毁掉 diff 结果**。`core.autocrlf=true` 使工作区为 CRLF、git 内为 LF，
用 `diff` 命令比较会把**整个文件**判为不同（1,5672c1,5672）。必须用
`difflib.unified_diff(upstream.splitlines(), local.splitlines())`（splitlines 会剥掉行尾）。

**本地相对基线的定制只有 2 处（均在 cms.py）**，其余 5 个 py 文件与基线逐行一致：
1. `_BRACKET_TAG_RE` + `_normalize_cms_title()`：苹果 CMS 片名 【...】/[...] → (...)，
   规避 MoviePilot 核心 `is_anime()` 把「剧名【年份】【地区/类型】【字幕】」误判为动漫。
2. `_result_from_item()` 中 `title = _normalize_cms_title(_text(...))`。
上游 0.4.82 的 `cms.py:911` 挂载点未变 → 定制可直接重应用。

**合并策略**：差异过大（`__init__.py` 7355 vs 5672 行、`downloader.py` 3771 vs 2088 行，
跨 23 个版本），逐条 cherry-pick 不可行 → **以上游 0.4.82 全量替换 + 重新应用 2 处定制**。
上游 history（0.4.61~0.4.82，16 条）已并入本仓库清单 history（现 91 条）。
